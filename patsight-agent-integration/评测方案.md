# PatSight 接入效果评测方案

页面上四项准确率的取数依据。试点用来冻结规则，正式集的分数才能替换页面上的占位百分数。

## 1. 要比的是什么

同一份专利、同一个页码范围、同一份任务说明，只改变提取路径。三组同时跑：

| 组别 | 路径 | 模型 |
|---|---|---|
| A | Claude Code 直接读 PDF | `claude-opus-5-5` |
| B | Codex 直接读 PDF | `gpt-6.1-sol` |
| C | Claude Code 调用 PatSight | `claude-opus-5-5` |

C 组只代表 Claude Code 这一条接入路径。Codex 接入 PatSight 不并进 C 组；要对外展示时另开一组。

开测前把下面几项抄进记录表，试点和正式集保持不变：

- Claude Code 版本，以及会话里的模型 id
- Codex 版本、模型 id、推理档位（使用产品默认档位，记下 CLI 显示的名称）
- PatSight 算法版本，四项任务各自的任务类型编号
- PatSight 的 `llm`、`ocr_type`、`ocsr_method`（与对外默认配置一致）
- 每份 PDF 的 SHA256

直接读 PDF 的两组不得调用 PatSight，也不要预先做 OCR。三组都只接收原始 PDF 和页码范围。

## 2. 测试集

### 规模

| 集合 | 篇数 | 用途 |
|---|---|---|
| 试点 | 12 | 检查标注规则和匹配脚本，冻结后再不许改口径 |
| 正式 | 36 | 页面百分数只来自这一集 |
| 双人复核 | 8 | 从正式集中抽，约占 22%，只用来计算标注一致性 |
| 扫描件 | 4 | 单独报告，不计入页面百分数 |

36 篇是 4 个专利局 × 3 种版式 × 每格 3 篇。页面按「每篇专利同等权重」平均，有效样本量是专利篇数。按这个规模，单项分数大致稳定在 ±4 到 ±5 个百分点，报告里同时给出这个波动范围。

### 36 篇怎么分层

专利局：WO、US、EP、CN，各 9 篇。

版式：各 12 篇。

- 结构图为主：实施例结构式、路线图
- 活性表为主：带数值和单位的表格
- 名称与反应文字为主：正文中的 IUPAC 和反应描述

试点 12 篇是同一张表里每格 1 篇，不进入最终分数。

### 每篇评测哪些页

化学家先划定评测页，三组使用同一范围。单篇不超过 30 页，优先覆盖实施例、主活性表和一条路线。相关内容超过 30 页时，取包含这些内容的连续页，并在清单里记下未纳入的页码。

### 纳入和排除

纳入 2018–2025 年公开专利，化学类型以小分子为主。中文专利保持原文，不预先翻译。

排除：

- 产品演示、Skill 示例和提示词调试用过的专利（含示例 `WO2024099996A1`）
- 客户未授权的非公开文件
- 肽、抗体、高分子。产品若尚未承诺这些类型，不放进正式集

扫描件 4 篇从 WO/US/EP/CN 中各取 1 篇，用来看 OCR 压力，结果写在报告附录。

## 3. 标准答案

模型开跑之前完成标注。标注人看不到任何一组的输出。

两位化学家使用同一份 2–3 页的标注说明。8 篇双标专利由两人独立标注，第三人只裁决不一致的条目。先算出两人一致率，再写进报告。某一项两人一致率低于 90% 时，这一项的系统分数旁边必须带上该一致率。

每条标准答案一行，至少包含：专利号、页码、类型、是否纳入本项、结构 SMILES、活性字段、反应物/产物、IUPAC 原文。

一篇专利在某项没有纳入范围的答案时，这篇不进入该项平均，报告写明实际进入的篇数。

## 4. 评测标准

页面上的一个百分数是**宏平均 F1**：先对每篇专利计算 F1，再对专利取平均。

- 精确率 = 对上的输出条数 / 系统输出条数
- 召回率 = 对上的标准答案条数 / 标准答案条数
- F1 = 2 × 精确率 × 召回率 /（精确率 + 召回率）

无输出、超时、没有按约定返回 JSON：该篇该项 F1 记 0，保留在平均里。精确率和召回率写在报告里，不放进四张图。耗时和人工修正量只作为补充。

### 结构提取

评图纸、路线图和实施例图中的结构。只在文字里出现的名称不进这一项。

不纳入：Markush 通式、结构无法唯一确定的高分子、肽和抗体。

判定：

- 用 RDKit 标准化后比较 InChIKey
- 比较前去掉盐和溶剂
- 图纸有明确立体化学时，立体化学必须一致
- 标准答案没有立体化学时，只比较去掉立体信息后的结构
- 互变异构按 RDKit 默认规范比较，不另做互变异构枚举
- 无法解析的 SMILES 算未对上

### 活性提取

一条活性必须同时对上：化合物、终点、不等号、数值、单位、测定名称、生物体系（细胞系或靶点）。

纳入的终点：IC50、EC50、Ki、Kd、GI50、CC50，以及写明浓度的抑制率。只写「有活性 / 无活性」的描述不进这项。

数值先换到同一单位，再按原文有效数字比较。`1.2 μM` 与 `1200 nM` 算对，`1.23` 与 `1.2` 算错。`>`、`<`、`=`、`~` 必须一致。标准答案没有测定条件时，不要求系统补出条件。

### 反应提取

只评测试开始前 PatSight 反应说明里列出的反应类型。这份清单在标注前冻结，三组使用同一份。清单之外的反应不进标准答案，也不因为某一组多提取了而加分或扣分。

一条反应算对：反应物集合与产物集合都对上。顺序不计，匹配方式与结构项相同。试剂、溶剂和收率不进入这个百分数。

### IUPAC 名称提取

以每篇专利中去重后的名称为一条。和原文比字符串，接受的规范化只有：

- 连续空白合并
- 拉丁字母大小写
- 连字符的不同码位

化学上等价但原文不同的名称算错。中英文名称不互相折算。

## 5. 执行步骤

1. 冻结本方案、提示词、输出 JSON 和 PatSight 配置。提示词三组共用，只规定提取范围和输出格式。C 组额外启用 PatSight Skill。
2. 抽取候选专利，确定 12 + 36 + 4，保存 PDF 并记录哈希和页码。
3. 标注试点 12 篇，跑通三组，只用来修正匹配脚本和标注说明。
4. 冻结规则。此后不因某组分数高低改匹配方式。
5. 标注正式 36 篇。8 篇双标。
6. 正式运行。每篇每组 1 次作为官方结果。另选 6 篇各重复 3 次，用来看波动。某一项三次结果的极差超过 3 个百分点时，页面改报中位数，并写上区间。
7. 脚本完成结构、单位和名称匹配。人只复核立体化学、盐和单位写法，复核结论写回规则后三组一起重算。
8. 做内部核对，不作为第四根柱子：同一输入下，直接调用 PatSight 与经 Skill 调用的原始结果应一致。Agent 整理时丢掉或改写的记录，算在 C 组的用户可见结果里。

输出统一为 JSON，字段为：

- 结构：`id`、`smiles`、`page`
- 活性：`structure_id`、`endpoint`、`operator`、`value`、`unit`、`assay`、`system`
- 反应：`reactant_smiles`、`product_smiles`
- IUPAC：`name`、`page`

## 6. 人员和周期

两位化学家标注，一位第三人裁决双标差异。匹配和汇总由脚本完成。

| 阶段 | 时间 | 产出 |
|---|---|---|
| 冻结方案、抽样、保存 PDF | 第 1 周 | 专利清单、提示词、配置记录 |
| 试点标注和试跑 | 第 2 周 | 冻结后的标注说明和匹配脚本 |
| 正式标注 | 第 3–4 周 | 36 篇标准答案和 8 篇一致率 |
| 正式运行、计分、复核 | 第 5 周 | 可替换页面的四项分数 |

一篇专利的结构和 IUPAC 大约 1–2 小时；活性表密集时再增加约 1 小时。反应按实际路线数量另计。

## 7. 结果如何回到页面

四张图的百分数改为正式集的宏平均 F1。表格里的 `72 / 100` 改为该项实际进入的专利篇数，例如 `36 篇`。模型 id 若与开测记录不一致，改成记录表里的值。

图表下方说明补上：测试日期、正式集篇数、Claude Code 与 Codex 的产品版本、推理档位、PatSight 算法版本和 `llm` / `ocr_type` / `ocsr_method`。扫描件结果、精确率、召回率、标注一致率和重复运行区间放在报告中，不放进四张图。
